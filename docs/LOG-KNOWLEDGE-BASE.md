# Log Lab knowledge patterns

Log Lab uses an offline, deterministic ranked phrase matcher backed by `src/Upuaut.LogLab/Knowledge/log-knowledge-base.json`. Each data row stores a stable ID, category, headline, explanation, signals, tags, recommendations, source name/URL, and a representative example. Curated patterns are evaluated alongside broad scenario rules; the strongest set of specific signals wins. The engine returns matched evidence, a stable rule ID, a primary documentation link, and investigation steps. “Match strength” describes how much matching evidence appeared in the entry, not the probability of a particular root cause. The shipped set currently holds 51 curated patterns; the loader accepts up to 512 validated rows and silently disables malformed data.

The parser does not download logs or send user data to a service. Source documentation informs the explanation and remediation guidance. The scratch fixtures `scratch/20-cloud-database-runtime.log` and `scratch/21-expanded-knowledge-cases.txt` contain synthetic lines with representative public error codes and phrases, not copied third-party log records; the second fixture is exercised by `CrashForensicsTests` so every curated pattern keeps a matched example. This avoids bundling datasets whose redistribution terms may be unclear and helps prevent fitting rules to one log corpus.

## Ranking and safe interpretation

- Phrase matching is case-insensitive and bounded to each parsed entry's message, source, and a limited number of fields. Regex matching is not used for the knowledge rules, so adversarial input cannot cause catastrophic regex backtracking.
- Longer, more specific overlapping signals replace shorter duplicates before scoring. Several independent signals strengthen a match; one weak match stays weak.
- Broad rules remain available when no specific rule matches. Every recommendation asks for corroborating context and avoids automatic remediation.
- Source links document the interpretation. A log message may be vendor-modified or incomplete, so the original entry and neighboring records remain authoritative.
- The LogHub project is useful as a research/evaluation index, but its datasets are not bundled here: [LogHub repository](https://github.com/logpai/loghub).

## Optional AI review

DeepSeek chat completions, Gemini `generateContent`, and OpenAI-compatible chat completions are supported. The service has no automatic startup check or background request. Log Lab, Scout, Weigher, and Crash Forensics each expose a manual **Request AI Review** button that submits exactly one unit — one selected entry, one selected frame, one correlated event with its nearest log entry and frame, or one crash artifact — and never the surrounding case, buffer, or dump. Requests are assembled by a shared prompt engine: the user prompt stays under 12,000 characters, oversized units are compacted with visible guardrail notes rather than sent whole, and anything beyond the 2,000,000-character refusal limit is rejected locally without a network call. Each review panel reports the characters submitted against that ceiling and lists the guardrails that changed the unit. Provider name, model, and endpoint are stored under `%LOCALAPPDATA%\Upuaut\Settings`; the API key is protected using Windows DPAPI for the current user. The key is never shown again after saving or written to app logs. Remote analysis requires network access and is subject to the configured provider's retention, privacy, and billing terms.
